## 一、缺陷清单（全部已修复并回归）

### D-01【P0·内核】停止按钮完全失效，回复照常泄漏 ⛔→✅

- **现象**（M3-2 案例，证据 `M3-2_stop*.png`）：流式回复期间点击停止（含精确点击 `.composer__send--stop`），状态持续 Working 直到运行自然结束，回复全文照常写入时间线；中途停止、首字节等待期停止均复现。
- **根因**（事件级时间戳实证）：`main.ts` 把 `cancelCurrentRun` 注册进全局 window-scoped IPC 串行队列（`enqueueWindowScopedAction`），而同队列的 `submitComposer` handler 会 `await session.prompt()` **持有队列直到整个模型运行结束**。停止调用被排队到运行结束后才执行，到达时 `isIdle=true`，abort 成为空操作。pi 内核经最小复现排除（裸 AgentSession 下 abort 12ms 生效）。
- **修复**：`cancelCurrentRun` 改走 `runImmediateStateResultForWindow` 绕开串行队列（main.ts，附注释说明约束）。
- **回归**：① GUI 实测：延迟流中点停止 → 状态 3s 内回 idle，回复零泄漏（`M2-7-branch.png` 前置会话）；② 新增 `tests/core/stop-during-run.spec.ts` 回归用例（6s 首字节延迟 mock，断言 4s 内 idle + 泄漏为零），**passed**。
- **衍生记录（D-04，已知限制）**：同一队列还承载主题切换/归档/模型切换等 window-scoped IPC，长运行期间仍会被排队（未在本次修复范围内，建议后续将 `submitComposer` 改为不持有队列的派发模式）。

### D-02【P1·引导】确认工作区即写"已初始化"标记，中途重载/退出会跳过剩余引导步骤 →✅

- **现象**（M1 案例）：引导第 1 步"确认并继续"执行 `initWorkspaceDir` 时即写入 `.workbench-initialized`（`needs-onboarding` 的判断依据），此时引导尚未完成。
- **修复**：`initWorkspaceDir` 增加 `markInitialized` 参数；`onboarding:confirm-workspace` 传 `false`；`onboarding:finish` 完成时补写 sentinel。
- **回归**（`M1-1-fresh-retest.png` ~ `M1-4-finish-retest.png`）：全新沙箱三步引导全程正常，sentinel 仅在 finish 落盘，重启直接进主界面。

### D-03【P1·设置】检查更新恒报"检查失败" →✅

- **现象**（M8-6）：关于页"检查更新"始终失败，主进程日志 `GitHub Releases returned 403`。
- **根因**：api.github.com 匿名配额按出口 IP 共享（代理场景必然 403/429）；且仓库全部 release 均为 prerelease，`releases/latest` 只认正式版、解析不到 tag，首版兜底（redirect）无效。
- **修复**：403/429 时先解析 `releases.atom`（走 github.com 网页域、无限流、含 prerelease），失败再退 `releases/latest` 重定向；版本比较收敛为单一入口 `compareReleaseVersions`。
- **回归**（`M8-6-update-retest.png`）：点击检查更新显示"已是最新版本 (0.1.0-beta.39)"。

### D-06【P1·功能缺口】会话重命名无任何 UI 入口 →✅

- **现象**（M2-4）：`renameSession` IPC 三侧契约齐备，但渲染层零调用——用户无法手动改会话名。
- **修复**：会话右键菜单新增"重命名"（Pencil 图标），走应用内 `appPrompt` 弹窗（带当前标题预填）。
- **回归**（`D06-rename-menu.png`、`D06-renamed.png`）：右键菜单出现入口 → 弹窗输入"化物所跟进" → 确认 → 侧栏即时更新。

### D-07【P2·规范回归】知识库页重新出现"关闭"按钮 →✅

- **现象**（M6-1 截图）：违反已定稿规范"侧栏切换页面不设关闭按钮"（定时任务页即无）。
- **修复**：移除 WikiView 顶栏关闭按钮（`onClose` prop 链路保留不破坏调用方）。
- **回归**（`D07-verify2.png`）：知识库页无关闭按钮，列表/图谱切换正常。

### D-08【P2·文案】会话树视图暴露内部节点英文名 →✅

- **现象**（M9-3 截图）：/tree 视图显示 "Model / Thinking / Title" 等 pi 内部 entry 类型名。
- **修复**：`treeNodeTitle` 全量中文化（用户/助手/工具结果/终端/分支摘要/上下文压缩/切换模型/思考级别/会话标题/标签/自定义/节点）。
- **回归**（`D08-tree-chinese.png`）：树节点显示"切换模型 / 思考级别 / 会话标题"。

### D-05【观察项，不修】dev 沙箱首轮截图中终端面板呈展开态

- 核查结论：代码默认 `showTerminal=false`，仅标题栏按钮可切换；测试期间无法复现自动展开，判定为测试操作伪影，不构成缺陷。

### D-09【观察项，不修】自动化快速 toggle 序列中"计划中"徽标出现过一次状态不一致

- 三次复测未能用单一用户路径复现；计划模式核心行为（写类工具 veto）有 shell-smoke e2e 覆盖且通过，判定为自动化序列伪影。如后续用户复现再立案。

## 四、遗留与建议（不阻塞发布）

1. **D-04（已知限制）**：长模型运行期间，其余 window-scoped IPC（主题切换/归档/模型切换等）仍被串行队列排队。建议下批把 `submitComposer` 改为立即返回、运行状态完全事件驱动，从根上解锁整族交互。
2. **D-09（观察项）**：计划模式徽标在自动化快速 toggle 序列下出现过一次不一致，未能用单一用户路径复现。
3. **右键菜单/Esc**：右键菜单支持点击空白关闭，但不响应 Esc；树 modal 同样仅支持 × 关闭。建议统一补 Esc 关闭。
4. **归档管理页遮罩**：点击遮罩不关闭（仅 ×），与其他 modal 行为不一致。
5. 分支产生的新会话落入"未分类"而非源会话分组——语义可接受，若希望继承分组可在 fork 时带上 groupId。
